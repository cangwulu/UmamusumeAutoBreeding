## 0. 一句话结论（先看这个）

- 巴哈攻略给了**相性/胜鞍/因子的完整规则**，其中「2/24 改版后的胜鞍规则」与我们记忆里**胜鞍分待实装**的口径直接冲突：**国服现行已是「仅 G1 计胜鞍、取消金章加成、父辈间 S(B,C) 也计」** —— 若我们照旧实现"历战多跑 G2/G3 刷胜鞍 + 金章"会算错。
- uma-tools 的 `SuccessionPlanner`（5952 行）是一个**因子规划 + 相性计算器**，可直接借鉴的：**官方拆包相性数据（95 角色 / 2133 关系组）**、红因子继承概率模型、6 槽因子分配的「需求-供给」模型、历战路线抽象为「G1 覆盖数」的胜鞍估算。
- **最大资产**：仓库自带 `master.mdb`（国服官方拆包 SQLite），内有 `succession_relation`（2133 关系组 = 官方权威相性）与 `succession_relation_member`（角色归属）、`succession_relation_rank`（0-50 三角 / 51-150 单圈 / 151+ 双圈官方阈值）。**我们 affinity.json 只有 84 角色/792 组（BWIKI 网页数据），比官方少了 1341 个细分关系组，算分系统性偏低（实测常见组合低 3~5 分）**。

## 1. 巴哈攻略核心规则（正文 + 2/24 改版）

### 1.1 基本相性（两两/三三，与我们的 affinity 一致）

- 关系分组：1/2 分组（宿舍/性别/寝室/学年/诞生年/诞生月/同胜史实比赛/同时期活跃…）+ 7 分组（距离/场地/跑法适性）。**同组才有分**，全组 point 累加。
- 官方表实测权重分布：1947 个 1pt + 148 个 2pt + 10 个 7pt + 28 个 8pt（7/8pt 即适性大组，S 适性细分到 8）。
- 等级阈值（`succession_relation_rank` 官方确认）：**0~50 = △（三角），51~150 = 〇（单圈），151+ = ⌾（双圈）**。
- 三人相性：三个人共同所在的组也计分（如目标+父+祖父都在草地/英里/中距组 → 21 分）。

### 1.2 继承树总相性公式（官方同款）

设 A=自己(目标)，B/C=父母（父/母），D~G=四祖辈（B 侧两位、C 侧两位）：

```
总相性 = R(A,B) + R(A,C) + R(B,C)
      + R(A,B,D) + R(A,B,E) + R(A,C,F) + R(A,C,G)
```

- **自己与祖辈同一角色时，对应三元组记 0**（如 A 与 D 同马 → R(A,B,D)=0）。巴哈强调「养马要回圈至少要四只不同马」。
- 2/24 改版**新增 S(B,C)**：父辈之间也吃相性。

### 1.3 胜鞍（2/24 改版后 = 现行国服规则）

- **改版前**（巴哈正文）：父辈&祖辈赢过**相同重赏（G1/G2/G3）**即得胜鞍，金章（经典三冠/春秋三冠等）另计，同一场比赛只计一次。正文里的「27 重赏 + 三冠 + 春秋连霸 = 31 胜鞍」全是旧规则。
- **2/24 改版后（重要，与国服当前一致）**：
  1. **胜鞍仅限 G1**（G2/G3 不再计）。
  2. **父辈之间的重合 G1 也计**（即新增 S(B,C) 项）。
  3. **取消金章/称号类胜鞍**（经典三冠等不再额外计分）。
  4. 单场 G1 的胜鞍点数**提高**。
- 63 战断腿流历战时代结束；草地英中长 G1 理想可跑 **16+4 战**（16 场 G1 + 出道/结尾等 4 战非 G1）。

### 1.4 因子规则（与既有认知一致，附官方表佐证）

| 因子 | 效果 | 说明 |
|---|---|---|
| 蓝因子 | 开局给属性：1☆ +5 / 2☆ +12 / 3☆ +21 | 结算 ≥600 有机会出 3☆ |
| 红因子 | 强化距离/跑法/场地适性 | B→A 1☆、C→A 4☆、D→A 7☆、E→A 10☆、F/G→A 与 A→S 只能靠 4 月额外继承 |
| 绿因子 | 开局继承父母固有 hint | 仅 3☆+ 马娘，4 月概率继承祖辈固有 |
| 白因子 | 赛事(赢过的 G1，给属性/绿技) + 技能(学过的技能+hint) + 剧本因子 | 仅 4 月概率获得；剧本因子 URA=速耐 / 青春杯=力智 / 巅峰杯=根耐 / 偶像杯=速根 |

- 适性数值表（智力=跑法、力量=场地、速度=距离），技能发动率 `max(100-9000/智力, 20)%`。

### 1.5 历战赛程方法论（对我们 route_planner 的启发）

- 巴哈给了一张「中长适性通用」的 URA/青春杯 3 年赛程表（2 年 11 月中 京都JS → 3 年 12 月下 有马，约 27 重赏全胜），并标注了各马的**掉赛程坑**（米浴/麦昆/重炮/大进等目标赛会挤掉 G1，损失胜鞍）。
- **史实还原赛（同名但异场）不计胜鞍**：如米浴宝塚在京都、晨光天春在阪神 → 我们 race_bwiki/race_schedule 的「resolve 别名归一」需小心，做胜鞍时不能只按比赛名匹配。
- 四马循环法：1 目标 + 2/3/4 高相性/强固有马，养出历战 3 星蓝因子马 → 配出 4 → 3×4 出 1。可借好友（好友马可替代循环里的一只）。

## 2. uma-tools SuccessionPlanner 实现借鉴点

### 2.1 数据资产：官方拆包（强于 BWIKI 网页）

`umalator/data/succession_data.json` 结构（由 `scripts/update_data.py` 的 `make_succession_data()` 从 master.mdb 导出）：

```json
{
  "relationPoints": { "101": 2, ... 共 2133 个 relation_type → point },
  "umas": [{
    "id": 1044, "name": "东商变革",
    "aptitudes": { "turf": 7, "dirt": 1, "short": 3, "mile": 7,
                   "middle": 7, "long": 4, "nige": 1, "senko": 7,
                   "sashi": 7, "oikomi": 3 },   // 7=A 6=B 5=C 4=D ...
    "relationTypes": [101, 202, ...]           // 该角色所属关系组
  }, ... 95 角色]
}
```

- 打分函数（TS）等价于我们 affinity.py 的 `pair_score`：取两马 `relationTypes` 交集 → 累加 `relationPoints`；三元组同理。
- 适性等级即数值：RANKS = ["-","G","F","E","D","C","B","A","S"]，7=A。**这份 aptitude 是形态(card)级**（来源 card_rarity_data WHERE rarity=5）。
- 与我们 affinity.json 对拍结果（同 ID 体系 1001=特别周…）：792 组完全重叠、权重仅 1 处不同，但官方多 1341 个组 → 经典组合普遍高 3~5 分（帝王+麦昆 36 vs 31）。

### 2.2 红因子继承概率模型（可直接抄）

```ts
RED_FACTOR_BASE_PROBABILITY = { 1: 0.01, 2: 0.03, 3: 0.05 };
probability = min(1, base * (1 + compatibility / 100));  // 相性越高越好继承
```

`probabilityOfReachingTargets()`：把每个因子看作 2 次继承机会（第 2 年 4 月 + 第 3 年 4 月）的伯努利过程，DP 算「达到目标适性所需次数」的联合概率 —— 即给定祖辈因子 + 相性分，预测最终能升到目标适性的概率。

### 2.3 因子需求 ↔ 供给模型（同我们 factor_requirements 的思路，可对齐）

- `minimumStarsForRank(base, target)`：`FACTOR_STEPS=[0,1,4,7,10]`，从当前适性升 target-base 级所需的红因子星数（与 1.4 规则表一致）。
- `factorSlotsForStars(stars)` = `ceil(stars/3)`：把星数折算成「3 星因子槽位」（继承面板 6 槽 = 父 3 + 母 3）。
- `factorDemandForUma()`：给定一只马的适性 + 目标历战路线(需要哪些适性达标) → 算出它作为种马**需要被供给的红因子类型与星数**（`demand`），以及**自己产不出、无法达标的类型**（`impossible`）。
- `routeMinimumSlotCount / fitMinimumsForUma`：当需求超过 6 槽时**自动降档**（把要求降到 4 级 C 下限），保证计划可行。
- 枚举器把 6 个继承槽位用「必选 token + 自由 token」的排列组合展开成目标因子方案（去掉对称重复）。

### 2.4 历战路线 → G1 覆盖数（胜鞍估算的关键抽象）

```ts
ROUTES = [
  { id: "mile-middle-dirt", name: "英中长泥", g1Count: 23, aptitudes: [turf, mile, middle, long, dirt] },
  { id: "short-mile-middle-dirt", name: "短英中泥", g1Count: 22, aptitudes: [turf, short, mile, middle, dirt] },
  { id: "none", name: "暂不规划历战", g1Count: 0, aptitudes: [] },
];
commonG1Count(a, b) = a.id === b.id ? a.g1Count : DIFFERENT_ROUTE_COMMON_G1(=16);
```

- **同一路线内的两只种马**胜鞍 = 该路线 G1 数（草地英里中距离的 G1 理想 16 + 泥地 7 = 23）；**不同路线**取公共 G1 近似 16。
- 每个槽位相性分 = 基础相性(base) + 共同 G1 数 × 3（G1 每场 +3pt，2/24 改版值）。
- 总相性 = 目标与父母（及祖辈）各基础分 + 父辈对祖辈的 G1 重合 + 父辈间 G1 重合（S(B,C)）→ 与我们记忆里的 7 项分解完全一致。

### 2.5 规划器输入输出（UI 结构 = 借鉴蓝图）

输入：目标马 + 6 个槽位（父/母/祖父AA/AB/母系BA/BB）可指定或留空 + 每条血脉选历战路线 + 每适性设最低目标等级 + 想继承的红因子类型。
输出（`CompleteDesignPosition`）：
- 每个槽位**推荐候选马**（按满足因子需求的能力过滤）
- 各槽位与目标的**相性明细**：基础分 / G1 重合数×3 / 总计，以及「为何是这个数」的 tooltip 逐项分解
- 达到目标适性的**概率**（红因子继承概率模型）
- 提示哪些适性无法达成、需要降档或换马

## 4. 附：巴哈攻略中的高价值杂项

- **固有强度优先于基本适性**：星云/多伯/丸善等关键加速度固有，选种马时应优先于基础相性分。
- 地固/直線一気等**关键技能白因子 6~9☆ 有时比 9 蓝更重要**（降低配卡限制）。
- 8☆蓝 + 6 剧本因子 > 纯 9 蓝（剧本因子提上限）。
- 同一只马出现在自身+祖辈 → 该三元组相性归 0，循环养马至少要 4 只不同马。
- 乌菈菈（相性地板）都能靠历战 121 胜鞍 + 55 基础 = 176 双圈 → 说明**历战 G1 覆盖是相性主引擎**，与我们 strategy_integrated.md C 节结论一致。
